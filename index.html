3. 今天要做什麼？

  • PART #1: 很多人以為 AI 就是「幫你出個題目、改一篇作文」，但真正能解放老師的用法，是「讓 AI 幫你把整堂課備出來」。
  • PART #2: 讓AI幫你自動生成整份文件只是開始，我們要從這裡出發，讓AI開始控制你的電腦，再看看代理人能做到什麼程度。

主題素材： 橋頭糖廠——台灣第一座新式糖廠（1901）

階段 你做什麼 帶走的東西

每一段的產出直接餵進下一段。一小時後，你手上會有：研究筆記＋題組＋學習單＋教案＋數位版輔助教材。

3.1. 為什麼挑「橋頭糖廠」？

  • 高雄在地連結最強 ——橋頭糖廠就在高雄市橋頭區（學生搭高捷紅線就到），輔導員回去帶班特別有感
  • 直接對應 108 課綱 ——國中歷史八上「日治時期經濟發展」單元（米糖經濟、新式糖業、總督府糖業政策）。橋頭糖廠是課本主文中常被簡略帶過、但剛好可以作為「閱讀素養延伸個案」的代表
  • 跨領域閱讀素材 ——歷史（日治殖民／經濟）、公民（在地產業變遷）、國文（PISA 閱讀素養）都能用
  • NotebookLM 餵得進來 ——維基、台糖官網、台史博、地方文史，公開素材豐富
  • 國文輔導員回去能跟其他科共備 ——閱讀素養本來就跨領域，這個主題自然連得起社會、自然
  • 對比衝擊強 ——課本／旅遊文宣寫的是「百年糖業」，史料寫的是「甘蔗農抗爭、剝削、林本源製糖會社事件」。這個落差就是國中閱讀素養最該練的「文宣表面 vs 史料真相」

5. PART #1：實作1——從陪聊到動手（9:30–11:00）

5.1. 這三年 AI 升級了什麼

  • 2023：會聊天（ChatGPT 爆紅）
  • 2024：住進工具裡（NotebookLM、Gemini in Workspace、Copilot）
  • 2025：會動手（Claude Code、Gemini CLI、Atlas 瀏覽器）
  • 2026：被訓成你的專屬助理（Skills、MCP）、主動幫你完成一些例行性工作

5.2. PART #1目標

  • 從「AI 是個工具」升級到「AI 可以幫我完成一整套流程」
  • 今天的課文只是一個例子，同一種方法你可以應用到不同領域、科目，生成不同內容

5.3. 方法：逆向設計（Backward Design）

我們今天跑的流程，其實是一個老師熟的方法： 逆向設計 ——Wiggins & McTighe 在 Understanding by Design (1998) 提出的三階段教案設計法。

我不是先列「AI 工具有哪些」再帶你們玩。我是 *先決定「一小時後你手上要有哪幾份檔案」，再倒推每一步*：

  • 要拿到教案 → 前面要有差異化素材
  • 要做差異化 → 前面要有題組
  • 要出題組 → 前面要有研究筆記
  • 要做研究筆記 → 前面要有對的素材清單

從終點往回排—— AI 不是替你決定要去哪，是你決定了之後，AI 替你跑完路線。

5.4. Step 1：NotebookLM——讀懂課文＋產出研究筆記

5.4.1. 先看 Lv.1 的限制

打開 ChatGPT，直接問： 

請介紹橋頭糖廠的歷史與重要性。

ChatGPT 會給你一個流暢的答案，但：

  • 多半只講「台灣第一座新式糖廠」的觀光導覽版，不會主動提到甘蔗農剝削、二林事件這條線
  • 「為什麼選橋仔頭設廠」背後的水源／鐵道／交通條件可能寫錯
  • 沒有出處——你不知道哪一句可以寫進備課單
  • 想拿來教「閱讀素養」中的「省思評鑑」層次，這份答案根本不夠用

這就是 Lv.1 的極限。接下來換 Lv.2 的方式。

5.4.2. 上傳素材到 NotebookLM

打開 NotebookLM（用 Google 帳號登入），上傳以下素材：

  1. 橋頭糖廠——維基百科
  2. 橋頭糖廠——台糖官網（觀光園區介紹）
  3. 臺灣糖業的源起之地——橋頭糖廠時空巡禮（方格子）——*本場研習的關鍵素材*
  4. 糖業王國興衰路——橋頭糖廠（方格子）——產業變遷視角
  5. 橋頭糖廠——台灣製糖工廠百年文史地圖

更多素材見底下「素材清單」。

5.4.3. 換別的課文/領域怎麼找素材？

研習當天我幫你準備好橋頭糖廠的清單，但回家備別的主題或課文時你得自己找。三招：

第 1 招：用 NotebookLM 內建的「探索」（在網路上搜尋新來源/Discover sources）

進入 NotebookLM → 新增筆記本 → 點 「Discover sources」 → 輸入主題 → NotebookLM 自動建議 10 份網路素材，一鍵加入。最省時的方法。

第 2 招：請 AI 開一份「分層素材清單」

打開 ChatGPT 或 Gemini，貼這段 prompt： 

我要為國中生上〈XX〉，準備寫一份完整教案。請給我 10 份網路上能找到的素材清單，分三類：

一、權威來源（維基百科、教育部、學術論文、文學館資料庫）
二、教師社群分享（教學案例、共備講義、評析文章）
三、批判閱讀對照組（媒體報導、部落格、聳動標題、爭議觀點）

每份附上完整 URL 與一句話介紹。

第三類「批判閱讀對照組」特別值得花心思——它就是課堂上「文宣表面 vs 史料真相」的對照素材。例如橋頭糖廠的旅遊文宣寫「百年糖業文化」，史料寫「甘蔗農抗爭」，這兩種敘述的落差就是這類。

第 3 招：AI 找的素材一定要逐個點開驗證

  • AI 會幻覺出 根本不存在的網址
  • AI 會把不同文章的內容混搭成「假摘要」
  • 看清楚： 誰寫的、什麼時候寫的、立場是什麼

點不開的丟掉、來源可疑的丟掉。剩下的才上傳到 NotebookLM。

5.4.4. 依序問四個問題

5.4.4.1. 第 1 問（大方向）
根據這些資料，日本人為什麼在 1901 年選擇橋仔頭設立台灣第一座新式糖廠？背後有哪些關鍵的時代背景？
5.4.4.2. 第 2 問（追細節）
橋頭糖廠選址橋仔頭的具體條件是什麼（水源、交通、地理、政策）？請引用史料說明。
5.4.4.3. 第 3 問（文宣 vs 史料——本場核心）
觀光導覽／旅遊文宣多半把橋頭糖廠寫成「百年糖業文化」、「五分車記憶」這類懷舊風，但同時期的甘蔗農生計、剝削問題、二林事件之類的史料寫的是另一回事。這兩種敘述的落差是什麼？該怎麼跟學生討論？
5.4.4.4. 第 4 問（教學切入）
如果我要為國中生設計閱讀三層次提問（事實／推論／評價），這個主題各層次可以怎麼問？請每層各給三題，並標示出處段落。

5.4.5. 請 NotebookLM 幫你打包

問完之後，貼這段指令讓它整合： 

請把我們剛才所有對話整合成一份「主題研究筆記」，格式如下：

一、主題基本資訊：題目、年代範圍、地理位置
二、歷史背景：列出關鍵史實，每點後標註來源文件
三、關鍵事件與人物：建廠決策、重要轉折、相關人物
四、文宣表面 vs 史料真相：兩種敘述的落差與教學意義
五、教學提問素材：三層次提問初稿（事實／推論／評價）
六、參考資料清單

5.4.6. 匯出成 Word 檔

操作步驟：

  1. 在回答下方點「儲存到記事」
  2. 到「工作室」找到記事 → 點「匯出至文件」→ 拿到 .docx

這份研究筆記是接下來四步的素材庫。

5.5. 課程設計邏輯: Ubd

以下的課程設計採用UbD (Understanding by Design/重理解的課程設計)的方式，UbD也稱「逆向設計/Backward Design」，是由 Grant Wiggins 與 Jay McTighe 於 1998 年提出的教學設計框架。其核心理念是「以終為始」(Begin with the end in mind)，主張在規畫具體的教學活動前，必須先明確定義學習者最終應達成的「理解」與「成效」。

5.6. Step 2：Claude——設計三層次提問與素養題

打開 Claude（免費版即可）。 建議專門開一個新對話跑這個 Step ——LLM 每次送訊息都要把整段對話歷史重送一次給模型；對話越長、每條訊息要送的 input token 越多。新對話從 0 累積最划算。

5.6.1. 操作流程

  1. 上傳 Step 1 從 NotebookLM 匯出的研究筆記 docx
  2. 貼這段指令：
你是國中跨領域共備老師，根據附件的研究筆記，為「橋頭糖廠」這個閱讀素養主題設計一份題組，輸出為 Word 檔（.docx）。

題組分兩部分：

【甲、文本精讀提問（每層次 3 題，共 9 題）】
- 事實層：直接從研究筆記能找到答案
- 推論層：需要連結背景知識
- 評價層：開放性，至少 1 題涉及「文宣表面 vs 史料真相」的對照

【乙、PISA 閱讀素養題組（共 6 題）】
- 2 題選擇題、2 題簡答題、2 題長文回答
- 對應 PISA 三層次：擷取訊息／統整解釋／省思評鑑
- 每題標註對應層次

每題下方寫「設計意圖」一句話。對象是國中生（13-15 歲），用語要貼近這個年齡。
  1. Claude 產出 Artifact → 下載 .docx

5.6.2. 現場觀察重點

  • AI 出題的「天花板」在哪？評價層題目最容易出得空泛
  • 哪幾題你會原樣用、哪幾題要改？這就是老師的判斷
  • 「設計意圖」這個欄位特別重要——AI 不寫，你會看不出他在想什麼

5.6.3. 帶走的觀念

  • 閱讀題不是越多越好，是「層次清楚＋設計意圖明確」
  • AI 出初稿快，但「分層比例」與「題目難度排序」仍要老師把關

5.7. Step 3：Claude——設計探究式學習單

場景：題組有了，現在要把它包成「學生可以拿在手上、邊讀邊填」的探究學習單。

5.7.1. 為什麼學習單給 AI 做特別省時

  • 排版（標題、空白格、橫線）老師最花時間的部分，AI 5 秒搞定
  • 留白比例、字級、行距這些細節，prompt 一句話就調好
  • 同一份題組長出 N 個版本（給不同程度的班）——批次處理是 LLM 的本領

5.7.2. 操作流程

建議開新對話 ——避免繼承 Step 2 的對話歷史（每條訊息都要重送整段歷史，越長越貴）。

  1. 上傳 Step 1 的研究筆記 docx
  2. 上傳 Step 2 產出的題組 docx
  3. 貼這段指令：
根據附件研究筆記＋訊息中的題組，幫我做一份「橋頭糖廠探究式學習單」，輸出為 Word 檔（.docx）。

學習單結構（A4 兩頁內）：
- 抬頭：班級／座號／姓名／日期填寫格
- Part 1（暖身）：1 題連結學生生命經驗的開放題
- Part 2（精讀）：從題組挑 5 題（事實 2 / 推論 2 / 評價 1），每題下方留 3-4 行橫線
- Part 3（小組討論）：1 題「文宣 vs 史料」對照題，留半頁空白
- Part 4（延伸）：1 個進階任務，給能力較強的學生

格式要求：字級 12pt、行距 1.5、A4 兩頁內。對象國中生，語氣要貼近這個年齡。
  1. Claude 產出 Artifact → 下載 .docx

5.7.3. 帶走的觀念

  • Lv.2 的精髓：你下「目標」，AI 一次幫你長出整套
  • AI 5 秒做好的排版，老師省下 20 分鐘——把時間用在「決定哪題要進學習單」這種教學判斷上
  • 學習單下載後仍要快速 review：題目順序、留白是否夠寫、用語是否貼合該班

5.8. Step 4：Claude——整合完整教案（壓軸）

場景：題組有了、學習單有了，最後一步：讓 AI 把這些黏成一份「下週就能拿來上」的教案。

這一步是研習的最強展示： 同一個 prompt，Claude 同時做四件事——

  1. 抽取教案範本的格式結構
  2. 把研究筆記＋題組整合成教案內容
  3. 把上傳的流程圖 PNG *直接嵌進 docx*（不用老師再插入）
  4. 輸出符合範本格式的 .docx

整個過程 零人工介入 ——示範時就講這句話：「我按下送出，下次再碰電腦的時候，已經是下載完成的 .docx 了。」這就是 Lv.3 的真貌。

5.8.1. 4-1：先做一張流程圖——NotebookLM → Napkin

進 Claude 之前，先回到 NotebookLM 那一組對話，產出視覺化的教學流程： 

請根據前面的研究筆記與題組，整理出 3 節課的教學流程描述。

格式要求：
1. 每節課分「引起動機 / 發展活動 / 綜合活動」三段，每段一行條列
2. 標註每段的時間長度（合計 135 分鐘）
3. 註明每段使用的素材（研究筆記／題組／學習單）
4. 最後輸出一段 Mermaid flowchart 程式碼，能直接渲染成流程圖

把 NotebookLM 的條列式結果貼到 Napkin（用 Google 帳號免費登入）：

  1. 開新文件，貼上 NotebookLM 給的條列內容
  2. Napkin 會掃描文字、自動建議多種視覺化（流程圖、樹狀圖、矩陣……）
  3. 挑一個最能呈現「3 節課依序進行」的版本——通常是橫向流程圖
  4. *老師親手匯出 PNG*：點右上「Download」→ 選 PNG → 存到桌面（建議命名 =flowchart.png=）

→ 老師手上會有：本機的 flowchart.png （待會上傳給 Claude）

⚠️ 中間是「人工銜接」，不是自動串接 ——Napkin 跟 Claude 之間沒有 API 通道，靠的就是你「下載 → 上傳」這個動作。研習現場示範時請刻意放慢這一步，讓老師看到「人在迴路裡」的感覺。

為什麼用 Napkin ——它的視覺品質遠勝手繪、又不需要拖拉：

  • 從文字直接生圖、不用一張卡一張卡擺
  • 同一份內容會給你多種視覺風格，可挑最適合的那張
  • 教師需要的是「一張看得清楚、印出來能貼公告或嵌進教案的圖」，Napkin 給的剛好是這個

備案：若 Napkin 卡住，把 NotebookLM 給的 Mermaid code 直接丟 Mermaid Live Editor 渲染後截圖即可。

7.1. 代理人 Lv.3｜讓 AI 動手操作你的電腦

7.1.1. Demo：整理桌面那堆亂七八糟的資料夾

先下載練習資料夾 ：test-cleanup.zip（50 個模擬檔案：教案、學習單、學生作品、成績、簡報，全部混在一起）

下載後解壓縮到桌面，會看到 ~/Desktop/test-cleanup/ 資料夾。

開終端機： 

cd ~/Desktop/test-cleanup
gemini

啟動 Gemini CLI（裝法見附錄）後，丟一句中文： 

桌面這堆檔案太亂了。請幫我：
1. 看一下有哪些檔案，按主題（教學素材／研習／學生作品／私人雜項）分類
2. 為每一類建一個子資料夾、把檔案移進去
3. 給每個資料夾用 macOS Finder 標籤上不同顏色
   （請用 `tag -s <顏色> <資料夾>` 命令，-s 表示「替換」而非「附加」，避免標籤疊加）
   建議顏色：教學素材→Blue、研習→Green、學生作品→Yellow、私人雜項→Gray
4. 完成後給我一份「整理報告」（有哪些檔案動了、放哪了、上了什麼顏色）

按 Enter 後，現場看 Gemini CLI 自己跑：

  • 讀目錄、列檔案 → 「我看到桌面有 47 個檔案、3 個資料夾」
  • 分析檔名、分類 → 「我建議分成：教學素材、研習筆記、學生作品、雜項」
  • 每一步問你 Y/N 才動手 → 你按確認，它建檔、移動、上色
  • 完成後給報告 → 「47 個檔案分入 4 個資料夾，已上色」

90 秒後，桌面乾淨。

7.2. 代理人 Lv.4｜把今天的流程「凍結」成 Skill

場景：今天我們花 90 分鐘做完橋頭糖廠這個主題。下禮拜你要備〈兒時記趣〉、〈麥琪的禮物〉，或者「左營眷村文化」、「美濃水圳」這些跨域主題……每一個都要重新貼今天這幾段 prompt 嗎？

7.2.1. Prompt 是封信，Skill 是 SOP

Prompt Skill
寫一封信，寄完就丟 訂一個 SOP，永遠跟著用
每次重新打 寫一次，AI 一直照做
你給 AI 一個任務 你給 AI 一份「流程說明書」
「請為橋頭糖廠設計題組」 「請用閱讀教學包流程處理 X」

下次打開 Claude，你只要說一句： 

請用閱讀教學包流程，為沈復〈兒時記趣〉產出完整教學包。
素材附後。

然後上傳素材——AI 自己跑完整套流程。

7.2.2. Demo：現場上傳一個 Skill 看看

  1. 開 claude.ai → 右上頭像 → Settings → Capabilities → Skills → 點「+ Add Skill」
  2. 把預先準備好的 reading-pack.zip 拖進去——裡面就是一份 SKILL.md ，類似這樣：

name: reading-lesson-pack
description: 為任何閱讀素養主題（課文或跨領域素材）一次生成完整教學包：主題研究筆記、三層次提問＋PISA 題組、探究式學習單、跨領域閱讀教案。當使用者要求「為 XX 設計閱讀教學包」、「跑 XX 的閱讀教學流程」時觸發。

# 閱讀教學包產生器

依序產出 4 份 .docx：

每一步的詳細指令見下方……
  1. 開新對話，貼一句指令＋上傳素材，按下送出
  2. 等 1-2 分鐘，看 5 個 Artifact 連續冒出來

7.2.3. 對比

剛才花 90 分鐘的流程，現在 3 分鐘自動跑完。我沒有再打那五段 prompt——它們都在 Skill 裡。 這就是 Lv.4。

7.2.4. Skill 的本質——升級階梯

Lv 你做什麼
1 你會打 prompt
2 你會把 NotebookLM、Claude、Napkin 串起來用
3 AI 替你跑完整個流程（一句話、多步動作）
4 你訂的規則，AI 一直照做（Skill）
5 AI 規劃步驟＋操作電腦（OpenClaw）

Skill 把今天的流程，從「每次重新做」變成「一份永遠帶著走的資產」。

*對輔導團特別重要*：你今天傳給其他老師的不再是「我會用 AI」，而是「一份可以複製貼上的流程檔」——這才是「方法傳出去」的真正意思。

7.2.5. 紅線提醒

最後一關永遠是你——AI 交成品，掛名的是你。Skill 跑得再快，每一份產出都還是要老師檢查。

7.3. 你｜什麼東西不該丟雲端？

學生作文、輔導紀錄、IEP、未公開競賽作品——一個判準：

「這段如果被截圖貼到網路上，我會崩潰嗎？」 會 → 別丟雲端。

進階解法（點到為止）：本機 AI（ollama + 開源模型）跑在你筆電上，資料完全不外流。下次研習可以再深入。

7.4. 三個帶走的觀念

  1. AI 幫你加速，不是幫你代教 ——上課的還是你
  2. 你給 AI 多少「你的樣子」，它就回給你多少「你的樣子」 ——你的教學風格、你的班、你的判斷，要寫進 prompt
  3. 一定要自己檢查 ——尤其是引用、題目、史實——AI 會編

12. 附錄：Gemini CLI 安裝（給研習後想自己玩的人）

研習當天我會用我自己預裝好的 Gemini CLI 做 demo（PART #2 的 Lv.3 整理資料夾那段）。如果你回家想自己跑類似的工作，下面是最低門檻的安裝步驟。整套安裝約 5-10 分鐘。

12.1. 1. 裝 Node.js（如果還沒有）

打開 macOS 終端機（=Cmd+空白鍵= → 輸入「終端機」）： 

# 用 Homebrew 裝（推薦）
brew install node

# 或從官網下載 LTS 版本：https://nodejs.org

確認安裝成功：=node –version= 應該回傳 v20.x.x 或更新版本。

12.2. 2. 裝 Gemini CLI

npm install -g @google/gemini-cli

12.3. 3. 領免費 API key

到 Google AI Studio 用 Google 帳號登入 → 點「Create API Key」→ 複製出來。

額度：每分鐘 60 次、每天 1000 次。 不用信用卡 （不像 Claude Code 要訂閱）。一般教師日常用法碰不到上限。

12.4. 4. 第一次啟動

回到終端機： 

gemini

第一次跑會問你登入方式，貼上 API key 即可。之後 gemini 一句就啟動。

12.5. 5. 給 Lv.3 demo 用：裝 tag 命令（讓 AI 能操作 Finder 標籤顏色）

brew install tag

這樣 Gemini 跑「整理資料夾並上色」時，會自動呼叫 tag -a Red FolderName 這類命令給 Finder 標籤上色。沒裝 tag 的話，AI 就只會建資料夾、移檔案，不會上色。

12.6. 第一次玩的安全建議

  • 不要直接在桌面開刀 ——先建一個測試資料夾，丟幾個假檔案進去練手感
  • 看每一步的輸出 ——Gemini CLI 動寫入（建檔、移檔、改名、上色）之前都會問你 Y/N ，看清楚再按
  • 重要檔案永遠先備份 ——任何 AI 工具都一樣的鐵律
